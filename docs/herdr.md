# Herdr

The Herdr app on the Macs opens spaces on `mini` and `hetzner` through herdr-core (`hc`) over ssh.

## herdr-core on the NixOS hosts

`hc` owns its binary in `~/.local/bin/herdr-core` on each NixOS host, as the Herdr app does on the Macs, so Nix does not install it. Run these commands on a Mac, with `<host>` being `mini` or `hetzner`:

```bash
hc machine add <host> --install   # copy the binary to the host
hc machine update <host>          # update it
```

The `herdr-core` user unit (`nix/modules/nixos/herdr-core.nix`) starts the server through a login zsh, so terminals get the login environment. `KillMode=process` keeps the core and its terminals running when the unit restarts or stops.

On the Macs the Herdr app starts the core with only the login shell's `PATH`, so programs that `hc` starts there lack the variables from `.zshenv` and `.zshrc`. Launchers that start agents wrap them in `zsh -lic`, as Herdr does for its tabs.

```bash
systemctl --user status herdr-core
hc server status
hc machine ls        # on a Mac
```

## Herdr app build on the Macs

The Macs run a Herdr app built from the checkout in `~/workspace/herdrdev/herdr-app`, with Juan's branches from the `fork` remote. A local build never updates itself, so update it by pulling and building again:

```bash
cd ~/workspace/herdrdev/herdr-app
mise install zig@0.16.0
ZIG="$(mise where zig@0.16.0)/zig" bash scripts/install-macos
```

The vendored Ghostty needs Zig 0.16; the newer Zig from Homebrew fails to build it. `scripts/install-macos` installs `~/Applications/Herdr.app` without stopping the running window; quit Herdr and open it again to use the new build. Keep no other copy in `/Applications`: Spotlight and the Dock may open the old one, and Herdr points `~/.local/bin/herdr-app` at whichever copy started last. `herdr-app --version` shows the version of the copy that started last.

## Herdr app configuration on the Macs

The `herdr-app` Stow package links the configuration into `~/.config/herdr-app`. Herdr does not draw SVG icons that are symlinks, so `scripts/link-dotfiles.bash` copies the icons instead.

The file watcher of Herdr ignores edits to symlinked files. Its fallback check applies settings, keys, and layouts within about 10 s, but it never reloads a running mod. After you edit a mod, touch the link to send the watcher an event:

```bash
touch -h ~/.config/herdr-app/mods/<name>/main.js
```

Test changes in the sandbox, a second Herdr window with its own app home and its own herdr-core, never in Juan's window: commands, dialogs and new spaces there land under his typing. `dev herdr sandbox start` copies the configuration from this repository into `~/.local/state/herdr-sandbox/app`, starts the window on the `juan` layout, moves it to the AeroSpace workspace `sandbox` (`aerospace workspace sandbox` shows it) and gives focus back to the app that had it. After an edit, `dev herdr sandbox sync` copies it again and the sandbox reloads it, mods included. `dev herdr sandbox run <command>` runs `herdr-app` or `hc` against the sandbox (`dev herdr sandbox run herdr-app do mod.open --name switch`, `dev herdr sandbox run herdr-app shot /tmp/shot.png`), and `dev herdr sandbox stop` quits it. The sandbox starts with no spaces and no other machines; make what a test needs with `herdr-app do space.new`. Its mods still call GitHub, Gmail and Zero for real. Edits to settings, keys and layouts in this repository still reach Juan's window within about 10 s through the links, so touch a live mod link only when the change is done.

Avatars of people and bots are fetched with one parallel `curl` into `data/slack-avatars/` in the Herdr app home, since `image()` reads only from there; until a picture arrives, a person shows colored initials. Pictures in messages show inline, fitted into 400×300 px, and open in the browser when clicked: uploaded images (a GIF whole, so it moves; others as Slack's 720 px thumbnail), link previews and image blocks such as Giphy's. `slack-files` downloads them into `data/slack-images/`, since Herdr's `fetch` can't return bytes; it sends the session cookie only to Slack's own hosts and skips files over 15 MB. Only the conversations the dialog loads fetch their pictures, and nothing deletes old ones. `node --test` in the mod folder runs the tests of `format.js`, `emoji.js` and `emoji-suggest.js`.

The `?` help sheet of the inbox, mail, zero, linear and slack dialogs searches its keys: `/` opens a box that keeps the keys whose keys, label or group contain every word typed, Enter leaves the box with the matches shown, and Esc clears the search, then closes the sheet. Any other key closes the sheet. The sheet takes every key while it shows, so this `/` never reaches the dialog's own `/` (filter, find, or the session picker's search). `inbox/help.js` holds it, and `scripts/link-dotfiles.bash` copies it into the other four mods.

The `notices` block, right of the tab bar, right aligns the attention dot and the GitHub, Gmail and Slack logos with their counts in the bar's corner. The logos show their counts: notification threads not marked done, read or unread, as the inbox lists them; unread threads in the Gmail inbox; and Slack conversations that need Juan: DMs and group DMs with unread messages, channels that mention him, plus thread mentions. A logo shows only when its count is above zero; it is dim after a failed check, and its tooltip then shows the error. Clicking a logo opens the inbox or the mail dialog. `mods/notices/poller.js` decides when to check: GitHub as often as its `X-Poll-Interval` allows (60 s), sending the last ETag so an unchanged answer is a 304 that costs no rate limit, Gmail every 2 minutes with one `gog gmail labels get INBOX`, and Slack every minute with one `client.counts`, using the session from `slack-session`, read once and again only after Slack refuses it. When Slack's counts change while the Slack dialog is closed, the same check refreshes the dialog's cache: the counts, and the last 60 messages of up to 4 conversations per check that have new messages and are either cached or need Juan, so the dialog opens on them. Unchanged counts read nothing more. `mods/notices/slack.js` and `slack-cache.js` are copies of the slack mod's, made by `scripts/link-dotfiles.bash`. Nothing is checked while the Herdr window is in the background, failures back off up to 15 minutes, and the inbox, mail and slack mods set `shared("notices.poke")` after marking read, dismissing, archiving or trashing (the slack dialog also when it closes), so the count follows within seconds. A poke drops the stored ETag, so the next check reads the whole list instead of a 304, and a dismiss sends the number of threads the inbox still lists, which the corner shows at once: after the last dismiss the inbox closes while herdr-core is still marking the threads done, and a check then would read the old list. The mail dialog likewise sends its unread count whenever its list changes (load, archive, trash, undo, or a failed change put back), since Gmail's label counter lags a change by seconds; it sends no count when the list reaches the 50-thread search limit and may leave threads out, and the corner asks Gmail again. A new source is one adapter in `mods/notices/sources.js`; its icon goes in `assets/herdr-icons/`. `node --test` in the mod folder runs its tests.

The attention dot, drawn by `notices`, shows like the `●` in the tmux status bar while any agent in any space is blocked or finished unseen. Clicking it shows that agent, blocked ones first.
